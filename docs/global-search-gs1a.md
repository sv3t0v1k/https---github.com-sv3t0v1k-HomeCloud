# GS-1A — контракт backend-поиска

Кодовый checkpoint: `fd4dbbcaf7d3b2e775f5b732aeb9e67fdd9b2457`.
База PR #35: `test`, `27e212fa6580f44655d8829d6003c7b39938f561`.
GS-1A охватывает безопасный поиск по **названию** собственных файлов и папок.
Поиск по содержимому, полнотекстовый индекс, fuzzy matching и frontend относятся
к отдельным решениям. Миграций, изменений Docker, обновлений и серверов нет.

## Маршруты и совместимость

`GET /api/v1/files/search?q=report&limit=20&offset=0` возвращает объект:

```json
{
  "files": [],
  "folders": [],
  "limit": 20,
  "offset": 0,
  "hasMore": false
}
```

- `q`: строка, после trim 2–100 UTF-16 code units, без внутренних ASCII control/DEL.
- `limit`: целое десятичное число 1–50, по умолчанию 20.
- `offset`: целое десятичное число 0–10000, по умолчанию 0.
- Повторные параметры, объекты, дроби, знаки и ведущие нули отклоняются HTTP 400.
- `%`, `_`, `!` трактуются буквально; PostgreSQL ILIKE регистронезависим в пределах
  коллации базы. Это не транслитерация и не исправление опечаток.
- Общая страница сначала содержит папки, затем файлы; в каждой группе порядок
  `name ASC, id ASC` по коллации БД. Лимит применяется **до** разделения массивов.
- `hasMore` определяется одной дополнительной строкой. Точного total нет.
- Offset pagination не является snapshot между запросами: перемещение, удаление
  или переименование во время просмотра может сдвинуть следующие страницы.
- При `offset + limit > 10000` следующую страницу запрашивать нельзя, даже если
  `hasMore=true`: интерфейс должен предложить сузить запрос.

Совместимый маршрут `GET /api/v1/files?search=report&parentId=7` сохраняет
**массив файлов только текущей папки**; без parentId ищет в корне. Поддерживает
те же limit/offset, с теми же пределами. Для совместимости разрешён один символ.
Пустой `search=`, невалидные parentId и неоднозначные параметры теперь дают 400;
подстановка `%` больше не означает «выдать все файлы». parentId — положительный
PostgreSQL integer. Это намеренное ограничение прежней неограниченной операции.
Обычное чтение каталога без search сохраняет прежний API. Текущий frontend
фильтрует загруженный каталог локально и не вызывает старый серверный поиск.

## Безопасная выдача

Файлы: `id`, `name`, `parentId`, `size`, `mimeType`, `isStarred`, `createdAt`,
`updatedAt`. Старый массив дополнительно содержит `isFolder=false`,
`isDeleted=false`. Папки: `id`, `name`, `parentId`, `shareFileId`, `createdAt`,
`updatedAt`. Это отдельные DTO: не следует приводить их к полным FileItem/FolderItem
через type assertion. BIGINT size может приходить строкой.

В выдаче нет `userId`, `storagePath`, `relativeObjectKey`, `storageLocationId`,
upload/session metadata или credential fields. ShareFileId папки — идентификатор
её активного файлового зеркала; folder id используется для навигации.

Все уровни цепочки папок должны принадлежать пользователю, быть неудалёнными и
иметь активное собственное зеркало. Без зеркала у legacy-папки закрывается всё
поддерево. Удалённые, чужие, оторванные от корня и недостижимые циклические ветви
не попадают в выдачу. Один SQL statement даёт согласованную видимость текущей
страницы. Папка не дублируется как файл-зеркало.

## Авторизация и ресурсные ограничения

Один строгий парсер полного `Authorization: Bearer <JWT>` используется JwtGuard,
Passport и предварительной проверкой transfer. `Bearer` регистрозависим,
дополнительные компоненты, двойной пробел и заголовки длиннее 4096 отклоняются.
Подпись и срок проверяются криптографически; sub — положительное безопасное целое.
Оба механизма авторизации проверяют живого активного пользователя через
JwtStrategy; email берётся из БД. Проверка административных прав сохраняется.

Оба поиска используют **один** MemoryStore: 12 запросов/60 секунд на проверенный
user id независимо от JWT/IP. GET/HEAD, регистр и завершающий слеш не создают
отдельный бюджет. Некорректные credentials учитываются по IP, затем отклоняются
guard; общая API-защита 100/60 секунд на IP сохраняется. HTTP 429 содержит
Retry-After. Обычное чтение каталога поисковый бюджет не расходует.

SQL параметризован. Оба поиска устанавливают `SET LOCAL statement_timeout =
'2000ms'` в той же транзакции и на том же соединении, где выполняется запрос.
SQLSTATE 57014 превращается в безопасный HTTP 503. Rollback сбрасывает LOCAL
настройку. Timeout ограничивает SQL statement, **не** ожидание соединения из пула
и не полную длительность HTTP. Размер выдачи не равен стоимости обхода дерева;
предел времени и частоты остаётся необходимым при малом limit.

Архитектурная граница: один backend process. MemoryStore сбрасывается при
перезапуске и не синхронизируется между процессами. Перед масштабированием
потребуются общий атомарный store и отдельная проверка. GS-1A их не добавляет.
