## Открыть

Preview запущен: **http://127.0.0.1:5173/files**.
Это локальный frontend с API существующего Mac Docker baseline на localhost:8080;
домашний сервер не используется и не обновлялся. Во встроенном браузере выполнен
разрешённый владельцем вход в существующий локальный smoke-аккаунт. В другом браузере
потребуется войти своей локальной учётной записью. Credentials в эту инструкцию не включены.

Для повторного запуска из `frontend`: `npm run dev:ux`.
Скрипт слушает только 127.0.0.1:5173 и направляет API в localhost:8080, не меняя
Vite config, Docker Compose, nginx или образы. Перед запуском нужен существующий
локальный backend. В этой сессии запущены только остановленные контейнеры
`homecloud-preview-db-1`, `homecloud-preview-backend-1`, `homecloud-preview-frontend-1`.
Другие контейнеры и старый ingress не запускались. Образы не пересобирались.

## Что изменилось

- Убрано постоянное боковое меню. Аккаунт и выход доступны сверху, после входа открываются файлы.
- Breadcrumbs, поиск по именам в текущей папке, список и плитка.
- Одна кнопка «Добавить»: файлы, загрузка папки, новая папка. Загрузка начинается сразу.
- Drop обходит дерево через общий с публичными папками код. Пустые каталоги создаются
  существующим API, файлы идут только через существующую UploadQueue.
- API создания личной папки возвращает зеркало файла: для назначения используется
  исключительно `folderId`, а не `id` зеркала. Отсутствие `folderId` останавливает дерево.
- Сворачиваемая панель сохраняет ошибки, повтор, паузу, отмену и выбор исходного файла.
- Один клик выделяет, двойной открывает. Enter открывает с клавиатуры; меню «Открыть»/
  «Просмотр» остаётся доступной альтернативой для сенсорных экранов.
- Чекбоксы, Cmd/Ctrl для нескольких объектов, Shift для диапазона; массовое перемещение
  в корзину с подтверждением. Правая кнопка открывает существующее меню действий.
- Корзина открывается справа снизу поверх текущей папки. Сохранены отдельное и массовое
  восстановление, удаление навсегда, очистка и подтверждения. Закрытие обновляет список.
- Личные и публичные папки используют общий ActionMenu и чтение деревьев; публичная
  запись по-прежнему показывается только после проверки существующей write capability.

## Личная проверка

1. Откройте папку «Проверка UX v2 24 октября» в локальном smoke-аккаунте. В ней оставлен
   созданный в этой сессии маленький файл `проверка.txt` (71 байт).
2. Проверьте одиночный/двойной клик, Enter, поиск, правую кнопку и переключение вида.
3. Выберите несколько своих тестовых файлов через «Добавить», сверните прогресс,
   перейдите в другую папку. Проверьте, что загрузка остаётся привязана к исходной папке.
4. Перетащите дерево с вложенными и пустыми каталогами. Сравните структуру и имена.
   Отдельно проверьте системный folder picker в Safari и Chromium.
5. На созданных тестовых объектах проверьте корзину, восстановление и отмену опасных
   подтверждений. Для проверки безвозвратного удаления используйте только свои ненужные
   тестовые объекты: оно действительно удаляет данные.
6. Повторите на узком экране. Зафиксируйте, что неудобно: расположение поиска и действий,
   плотность списка, размер окна корзины, поведение прогресса.

## Ограничения

Поиск ограничен текущей папкой, серверного глобального поиска нет. Общий обход дерева
ограничен 1000 объектами и 32 уровнями. Chromium `showDirectoryPicker` и directory drop
могут передавать пустые каталоги; fallback `webkitdirectory` передаёт файлы с относительными
путями и может пропустить пустые каталоги. Полностью пустая папка через такой fallback
может вообще не вызвать событие выбора — создайте её вручную или используйте drop.
Пустые файлы остаются неподдерживаемыми существующей очередью.

Личный mkdir не имеет идемпотентности: при сетевой ошибке автоматический повтор не
выполняется, уже созданные объекты сохраняются, дерево останавливается. Перед новым
выбором проверьте результат, чтобы не получить дубликаты. Повтор файлов доступен в
очереди. Незаконченный обход локального дерева не переживает обновление страницы;
существующие правила обнаружения сессий UploadQueue и повторного выбора файла сохранены.
Backend, CI/CD, Multi-Storage и серверная конфигурация не изменялись.
