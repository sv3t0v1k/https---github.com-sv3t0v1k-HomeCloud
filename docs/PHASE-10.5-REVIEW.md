# Приёмка Phase 10.5 — лимит скачиваний

Проверен коммит Kilo `9753c97`. Независимый review обнаружил два блокера:

1. Не сгруппированный `OR` в SQL позволял обновлять счётчики чужих, истёкших и отозванных finite-ссылок. Исправлено скобками вокруг всей альтернативы лимита.
2. Отсутствие validation decorators на `fileId` и других полях не позволяло создать ссылку через production ValidationPipe. DTO приведён к реальному HTTP-контракту; `maxDownloads` ограничен безопасным целым.

Передача `maxDownloads` из контроллера присутствовала в финальном коммите Kilo; замечание предварительного аудита по forwarding к нему не относится.

## Подтверждение

- Targeted sharing: 89 тестов прошли.
- Полный backend suite: 217 тестов, 16 suites прошли, включая реальную БД.
- Lint и build прошли. Известное предупреждение module type ESLint не блокирует проверку.
- Независимый повторный review исправлений не обнаружил блокеров в данном scope.
- PostgreSQL 15.13, отдельный временный кластер: 20 параллельных запросов при лимите 3 дают ровно 3 успеха; чужие, истёкшие и отозванные записи не меняются. Проверены unlimited и миграция up/down с сохранением старых строк.
- Compose использует PostgreSQL 16; на этой версии проверка ещё не повторялась.

Интеграционные тесты запускаются только при явном `HOMECLOUD_TEST_DATABASE_URL`, создают отдельную случайную schema и удаляют только её. Обычный `DATABASE_URL` не используется. Без тестового URL четыре PostgreSQL-теста пропускаются.

## Граница приёмки

Приняты атомарное ограничение, HTTP creation contract и обратимая миграция после исправлений. Исходный `9753c97` сам по себе не является безопасным checkpoint.

Семантика счётчика пока сохранена: учитываются допущенные попытки, включая Range, до проверки файла и диапазона. Ошибки storage/416/обрыв не возвращают попытку. Изменение этой семантики и folder download относится к оставшемуся backlog Phase 10. Общая Phase 10 не завершена.
