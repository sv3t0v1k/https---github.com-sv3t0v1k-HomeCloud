1. Общий `bearerTokenFromHeader` используется JwtGuard, Passport JwtStrategy,
   поисковым limiter и transfer admission. Дополнительные компоненты, двойной
   пробел, табуляция, неверная схема и слишком длинный заголовок отклоняются.
   Несовместимый разбор limiter/guard и прежний обход лимита закрыты.
2. JwtGuard делегирует live-проверку JwtStrategy: положительный safe integer sub,
   затем поиск `{id, isActive:true}`. Удалённые/деактивированные пользователи со
   старым access JWT не проходят. Email берётся из БД; admin-права сохраняются.
   Стратегия экспортируется из AuthModule, DI защищённых модулей проверен.
3. Один limiter/MemoryStore на оба поисковых маршрута: 12 запросов/60 секунд на
   user id. JWT/IP rotation, HEAD/case/trailing slash не создают новый бюджет.
   Невалидный legacy search учитывается до валидации.
4. `findAll(..., search)` использует общий безопасный запрос; форма массива
   ответа и область текущей папки сохранены. Listings без search не менялись.
5. SQL параметризован; `%_!` экранированы буквально. Owner проверяется на каждом
   уровне, требуется активное зеркало каждого предка, удалённые/недоступные ветви
   исключены. Папки не дублируются зеркалами, LIMIT общий до split массивов.
6. SET LOCAL statement_timeout=2000ms находится в той же транзакции, что SQL;
   SQLSTATE 57014 преобразуется в безопасный 503. Новые PG-тесты блокируют files
   другой транзакцией и проверяют оба поиска, сброс timeout и recovery.
7. Явная проекция исключает storagePath, storageLocationId, relativeObjectKey,
   userId. Порядок: тип → имя → ID. limit 1–50, offset 0–10000; неоднозначные

## Неблокирующие ограничения

- MemoryStore подходит одному backend-процессу, сбрасывается при перезапуске;
  масштабирование требует общего store и отдельной квалификации.
- SQL timeout включает SQL/ожидание блокировок, но не получение соединения из
  пула и не весь HTTP. Насыщение пула и произвольная многопользовательская
  нагрузка этим review не сертифицируются.
- На offset=10000 возможно hasMore=true. GS-1B должен остановить дальнейшую
  пагинацию и предложить сузить запрос.
