# HomeCloud UX v2 — массовое скачивание ZIP

24 октября 2026. Локальный вариант для личной проверки владельца. UX v2 ещё не принят; Production **NO_GO**, Multi-Storage **DEFERRED**. Push, merge, release и обновление домашнего сервера не выполнялись.

## Контракт

- `POST /api/v1/files/download-archives/prepare` требует обычный JWT и тело `{ "items": [{ "kind": "file", "id": 12 }, { "kind": "folder", "id": 7 }] }`. ID папки относится к `folders`, не к её зеркалу в `files`. Ответ: `{ "downloadPath": "/native-download-archives/<id>", "expiresInSeconds": 120 }`. Одноразовый секрет передаётся только в HttpOnly cookie с точным путём скачивания и не попадает в URL или тело ответа.
- `GET /api/v1/native-download-archives/:id` атомарно расходует право и выдаёт один `application/zip` как attachment с `Cache-Control: no-store`. `HEAD` проверяет право, но не расходует его. Повторный GET или истёкшее право дают 404. Возобновление через Range не поддерживается; после обрыва нужно начать скачивание заново.
- В архив входят корни выбранных папок, их вложенные файлы и папки, включая пустые. Файл, выбранный также внутри выбранной папки, появляется один раз. Совпавшие имена верхних корней получают суффикс ` (2)`; неоднозначные имена внутри дерева отклоняются до передачи. Опасные сегменты пути и коллизии после Unicode NFC и регистронезависимого сравнения отклоняются.

## Реализация и границы

Используется существующий `archiver`, общий с публичным ZIP папки. Каждая запись читается из одного открытого файлового дескриптора и потоково отправляется клиенту; полный ZIP и файлы не собираются в RAM. На подготовке и перед передачей проверяются живые записи пользователя, цепочки родительских папок, зеркала, отсутствие soft delete, метаданные размера и расположение реального файла внутри разрешённого корня. При изменении состава архива между подготовкой и GET скачивание прекращается с 409. Перед каждой записью доступ проверяется вновь; после открытия файла проверка повторяется. При закрытии соединения прекращается обход следующих записей и закрываются активные потоки/дескрипторы.

Лимиты: до 32 выбранных корней, до 5000 записей ZIP, глубина до 32 уровней, суммарный исходный размер и размер отдельного файла до 100 GiB, два одновременно подготавливаемых и два одновременно передаваемых архива на процесс, два ожидающих права на пользователя и 1000 прав всего. Право живёт 120 секунд. HTTP idle timeout — 120 секунд, общая длительность ответа — не более четырёх часов. Лимит потоков локален для процесса; при нескольких экземплярах backend необходим общий лимитер. Уже начатый запрос к БД/файловой системе может завершиться до обработки сигнала отмены. Доверенность каталогов хранилища остаётся предпосылкой существующего `StorageService`: конкурентная подмена компонентов пути между `realpath` и `open` не устраняется новым API.

Frontend показывает «Скачать ZIP» при выборе минимум двух файлов/папок, готовит право и передаёт ссылку обычному менеджеру загрузок браузера. Подтверждений и скрытого iframe нет. Ошибки подготовки показываются в панели выделения. Успешная передача ссылки браузеру не означает, что архив уже скачан; окончательный результат виден в загрузках браузера. Одиночное скачивание не меняет свой API.

## Личная проверка

Отдельный локальный стек запущен на `http://127.0.0.1:8081/login` с собственными базой и хранилищем; прежний Preview на `127.0.0.1:5173` не затронут. В новом стеке есть временный тестовый аккаунт и две пустые папки. Учётные данные передаются владельцу в отчёте, в репозитории их нет. Войдите, выделите обе папки и нажмите «Скачать ZIP». Проверьте один ZIP в загрузках браузера, структуру папок после распаковки, затем добавьте свои тестовые файлы для смешанного выбора, пересечения папки и файла внутри неё и обычного одиночного скачивания. При ошибке подготовки уменьшите выбор или обновите список. Личный результат проверки остаётся решением владельца.

Оба локальных контейнера собраны из этого рабочего дерева. Прямой запрос через nginx вернул HTTP 200 и ZIP с двумя пустыми папками. Встроенный браузер показал передачу браузеру, однако его нативный GET был прерван (HTTP 499), поэтому успешное сохранение файла именно во встроенном браузере не подтверждено. Safari в этом сеансе не квалифицирован: активная вкладка Safari сменилась на пользовательский сайт во время проверки, и дальнейшие действия там прекращены.

## Проверки

Адресные тесты проверяют один файл, несколько файлов, смешанный выбор, вложенные и пустые папки, дубли, коллизии, SHA-256 содержимого, чужие и удалённые объекты, небезопасные пути и символические ссылки, лимиты, одноразовость права, HEAD/GET и обрыв соединения. Два теста с настоящим PostgreSQL проверяют миграцию, SQL, состав ZIP и отказ в доступе. Полный backend-набор в Linux: 1025 PASS, 245 штатно пропущено; frontend: 319 PASS. Оба lint и build прошли; backend lint оставил 19 предупреждений в существующем `security.config.spec.ts`, ошибок нет. Независимый security review новых файлов выполнен; замечания об отмене при разрыве исправлены и покрыты тестами. Safari и архив близко к лимиту 100 GiB вручную не проверены.
